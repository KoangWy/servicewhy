# ServiceWhy — the agent that explains why a restaurant night went wrong

**Open Agent Hackathon 2026 · Track 02 — The Agent That Can Explain Why · Team Irigo**

> A restaurant manager asks *"why did Saturday dinner revenue drop?"* and gets an
> evidence-backed answer built from point-of-sale data, table-service events, shift rosters and
> guest reviews — with a **verifier that blocks any claim the data does not support**.

## Data disclosure

All data in this project is **fully synthetic**, generated by a seeded discrete-event simulator,
and labelled as synthetic everywhere it appears. No real guest, staff or customer data is used.

## Setup (final commands land with the build; target shape)

## How we use sponsor technology

- **Zetaris** — the single federated SQL surface over the restaurant's stores (POS + table events
  in one store; rosters, plate returns, reviews in another). The Investigator queries through it,
  and the Verifier's independent re-query goes through it again. Remove it and the agent cannot
  read the data.
- **Meterless** — the World Model agent engine (reference architecture, implemented in this repo):
  `WorldStoreService` + `IngestPipelineService` + `ContextBuilderService` as the shared
  hypothesis/evidence state with provenance that Planner, Investigator and Verifier all read and
  write. Remove it and follow-up reasoning loses its grounded state.
- **Cursor** — development environment. `.cursor/rules/` is committed; project invariants live
  there. (Sponsor credit was never released during the event; our usage is documented in this
  README and in the commit history.)
- **NVIDIA** — not used in the core build; optional stretch only.
